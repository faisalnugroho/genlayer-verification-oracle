01 · The missing layer

Agentic commerce ships the happy path. Nobody ships the argument.

Every standard racing out right now — x402 (agent payments), ERC-8004 (agent identity), A2A (agent-to-agent tasks) — engineers the moment everything works and leaves the moment of disagreement as someone else's problem: was the task actually done? was the claim true? did the payment actually happen?

Duplicated

Every escrow or dispute flow re-implements its own AI-verification logic inside its own contract. Same work, again and again.

Isolated

No shared trust surface between projects — one agent's "verified" means nothing to another contract.

Shared by GVO

Post a claim once, get a validator-consensus verdict once — any number of downstream contracts read the same answer.

02 · Verification paths

Two paths. One verdict surface.

resolve_claim runs GenLayer validator consensus. Which path executes depends on whether the claim carries a tx_hash:

PATH A · EVIDENCE-ONLY

LLM judgment vs. criteria

No payment asserted — the claim is judged on its evidence.

  1. Submitcategory · description · criteria · evidence_urlanyone, via the relay below — no key needed
  2. Leader fetches evidenceevidence_url is retrieved and shown to the LLMvalidators re-run the fetch independently
  3. LLM verdict vs. criteriadoes the evidence satisfy the stated criteria?strict boolean parse — the string "false" can't masquerade as true
  4. Partial-field equivalencevalidators compare only the verdict fieldreasoning may differ without breaking consensus
PATH B · x402 / USDC PAYMENT

On-chain gate, then judgment

A payment is asserted — the chain proves it before any LLM runs.

  1. Validator fetches Baseeth_getTransactionReceipt + eth_blockNumber via public Base RPCeach validator, independently
  2. Extract USDC transfersERC-20 Transfer events from the native USDC contract on Base0x8335…2913 · from / to / value from raw logs
  3. Exact-match assertion gatepayer · recipient · amount must match exactly (0 tolerance) + ≥5 confirmationsalso matches the right transfer among many in one tx
  4. Then the LLM judges the claimpayment proven, does the rest of the claim hold?
GATE FAILS → VERDICT FALSE. Wrong amount, wrong payer, nonexistent tx, non-USDC token, too few confirmations — the LLM is never consulted. Facts first, opinion second.

04 · Write path

Submit a claim

This form posts to the backend relay (POST /api/v1/relay/submit), which signs and sends the submit_claim transaction with its own funded Studionet account — your browser never holds a key. The claim ID comes back on-chain.

PATH B — leave tx_hash empty for an evidence-only claim (Path A). Fill all four payment fields to trigger the deterministic Base USDC gate (Path B).

⏱ rate limit: 5 submissions / IP / 10 min — each relayed tx spends the relay account's gas.
amount is an integer string in base units (USDC has 6 decimals, so 2000 = $0.002).

05 · Reproducible outcome

Reproduce a verification yourself

The full lifecycle runs from this page — no wallet, no CLI, no key. Follow these steps and you will observe the same verdict any other user gets for the same facts:

  1. Submit the claim. Fill the form above and press Submit claim.Leave tx_hash empty (Path A) or fill all four payment fields (Path B) — the readout returns your claim ID + tx hash.
  2. Resolve it. Find your claim in the claim browser (status PENDING) and press RESOLVE.This relays resolve_claim(claim_id) — validator consensus runs: evidence fetch (and Base USDC gate if Path B), then LLM judgment. Takes ~1–2 minutes.
  3. Read the verdict. The claim row updates to RESOLVED with verdict TRUE or FALSE, plus the validators' reasoning.Path B note: if the payer/recipient/amount don't match the Base tx exactly, the verdict is FALSE and the reasoning says why — that's the gate working.
  4. (Optional) Finalize. After the appeal window (3600 s) elapses, press FINALIZE on the claim to move it to FINAL — the status a consumer contract acts on.finalize_claim(claim_id) reverts while the window is still open — try it early and watch the guard fire.
  5. Verify independently. Cross-check on-chain: the Studionet explorer link in the claim row opens the exact transaction; the repo README documents the same flow via exercise_live.py.Same facts in → same verdict out, for you or anyone else.
06 · Dispute lifecycle

Appeal & finalization

A verdict isn't the end. Anyone can stake GEN to re-run the judgment (appeal_claim). Flip the verdict and your stake is refundable; hold it and the stake forfeits — split 50/50 between the original resolver and the treasury.

T+0 · Resolve

status: resolved
verdict recorded on-chain

The appeal clock starts at the node-assigned transaction timestamp — not client-supplied, so it can't be gamed.

T≤3600s · Appeal open

appeal_claim(id) with stake
re-runs consensus

Submit throwaway claims all you want — nobody's deadline moves.

T>3600s · Finalize

finalize_claim(id) — anyone
status: final

Consumer contracts: act only on final. resolved can still change.

08 · Honest limitations

What GVO does not promise

Stated plainly, from the README — because a trust layer that overclaims is worse than no trust layer:

Evidence URL trust (Path A)

GVO fetches whatever URL is supplied; it cannot detect content that changed after submission. Use immutable evidence (permanent gist / IPFS / archived link) where possible.

Base RPC availability (Path B)

Payment verification depends on the public Base RPC endpoint. If it is unreachable, the gate fails closed (verdict false) — GVO never approves a payment it cannot verify.

Appeal window clock

Wall-clock seconds against the node-assigned transaction timestamp (the non-manipulable primitive GenVM v0.2.16 exposes — there is no gl.block.timestamp). If a node ever failed to assign one, the parse reverts (fail closed), never silently approves.

Value transfers

emit_transfer emits a child value message; if the child transaction fails, value is not auto-returned. Withdrawals clear bookkeeping before emitting (checks-effects-interactions).

Not an escrow

GVO holds appeal stakes and pays refunds/rewards, but does not escrow the disputed amounts themselves — it is a judgment layer, not a custodian.

Free in v1

Submitting claims is free while the relay is rate-limited (5 / IP / 10 min). A fee model (Dev Fee) is future work, not a promise.
